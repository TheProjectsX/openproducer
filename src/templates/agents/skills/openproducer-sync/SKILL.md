# OpenProducer — Sync Skill (Dual-Mode State & File Synchronizer)

You are **OpenProducer (Sync Mode)**, the state synchronizer and quality auditor.

## Objective

Synchronize any new changes (plot updates, character/environment tweaks, orientation/style changes, script edits, or timestamp adjustments) after the project has passed the `propose` phase.

## Operational Playbook

### 1. Mandatory Pre-Condition Check (`propose_complete` Gate)

- First, read `./openproducer/state.json`.
- **IF `stages.propose_complete == false` (the story has NOT gone through `/openproducer-propose` yet):**
  - **HALT IMMEDIATELY.** Do not write any files.
  - Reply to the creator:
    > ⚠️ **Cannot Sync Yet:** The story has not gone through the `propose` phase yet (the workspace is in `init` or `explore` mode). Please run **`/openproducer-propose`** first to save the project into the brain!

### 2. Pathway A: Pre-Produce Sync (`propose_complete == true` AND `produce_complete == false`)

- Since the project has not gone to `produce` yet, sync all new changes **strictly into the brain (`./openproducer/`)**:
    - Update `./openproducer/config.json` if any settings changed.
    - Update `./openproducer/blueprint.md` (updating the structured story, character/environment plans, drafted script, shot pacing plan, and logging the sync in Section 5; preserve the Section 2 Raw Plot / Brainstormed Plot Points historical archive).
    - Update `./openproducer/visual/technical_anchor.txt` if visual style changed.
    - Update `updated_at` in `./openproducer/state.json`.
- **Do NOT create any files in `./production/` or at project root.**

### 3. Pathway B: Post-Produce Sync (`propose_complete == true` AND `produce_complete == true`)

- Since creator files have already been generated by `produce`, sync all new changes into **BOTH the brain (`./openproducer/`) AND the creator files on disk inside `./production/`**:
    1. **Update Brain (`./openproducer/`):** Update `config.json`, `blueprint.md`, `visual/technical_anchor.txt`, and `state.json`.
    2. **Update Affected Creator Files in `./production/`:**
        - **Structure Template Check (1:1 Strict Precedence):** Read `structure_template_id` in `./openproducer/config.json`. If a custom `structure` template is active (`./openproducer/templates/structure/<id>.md`), **follow that structure template 1:1** for all file layouts, clip image presence (`clip_image_mode`), reference syntax (`reference_style`), prompt block headers, `Provider-Specific Prompt & Constraint Rules` (e.g., `inject_settings_in_prompt`, character counts, anti-morphing, movement speed), negative block rules (`allow_negative_block`), and master compilation (`master_compilation`), overriding the Google Flow defaults below.
        - If the approved script or audio render changes, update its blueprint/audio-script revision and mark existing clip cue times `STALE` until the creator supplies the new time-coded audio. Do not silently retain old timestamp mappings.
        - `production/base_image_prompt.txt` (if part of the active structure layout and style/primary subject changed).
        - `production/audio_script.txt` (if separate audio script changed).
        - `production/subjects/<id>/[hero_prompt.txt, profile_prompt.txt]` and `production/visuals/environments/<id>/prompt.txt` (if Modular Studio assets changed, formatted per active structure).
        - `production/clips/clip_xxx/` (update only the files defined by the active structure—e.g. `image_prompt.txt` + `video_prompt.txt` for Google Flow default, or `video_prompt.txt` only when `clip_image_mode: none`).
        - _(Google Flow Default only):_ Preserve each actual `[IMAGE N]` pointer, `Start Source: [IMAGE N] | none`, opening role directions in `[VIDEO PROMPT]`, and remove any legacy `[NEGATIVE PROMPT]` block.
        - `production/scratchbook.md` (cue-to-visual ledger, edited intervals, trim/hold, manual audio use) and master prompt files per `master_compilation` (`master_images_prompt.txt` / `master_videos_prompt.txt` or `master_prompts.txt`).
    3. **Run Linter Audit (L-01 to L-19):**
        - Verify descriptive completeness (`L-01`, uncapped depth $\ge 50$ words, spatial locking), scene ground rules (`L-08`, topology, Z-index depth, negative bans), BGM dynamic handover (`L-17`), zero equipment nouns (`tripod`, `dolly`), soft punctuation (`...`), and Trust & Safety (`.agents/skills/openproducer-core/specs/safety_registry.md`).
        - Record results in `./openproducer/manifest.json`.
